1. Product Summary

ESAI Premium Dashboard is an academic competition workflow platform for Indonesian students, university competition teams, essay/KTI writers, and academic users. It manages competitions, guidebooks, files, AI agents, writing outputs, citation validation, calendar deadlines, and analytics in one structured workflow.

The current artifact is a high-fidelity HTML/React prototype. Production implementation should rebuild it as a typed Next.js app with Supabase persistence and secure AI execution through CLI and API-key model providers.

3. Core Workflow

  1. User creates or selects a competition from Dashboard.
  2. User uploads guidebook, poster, and registration metadata.
  3. Style Builder creates or imports 00_style_profile.md.
  4. Main Agent Onboarding consumes style profile and guidebook, then produces 01_onboarding_map.md.
  5. Each later agent consumes the previous approved output and produces the next file.
  6. User may override stage input by uploading a manual .md file.
  7. Stage output can be edited, saved, versioned, and approved.
  8. Validity-Checker compares final/research output with uploaded journal PDFs.
  9. Calendar tracks deadlines, stage tasks, and review events.

5. Supabase Requirements

Use Supabase Auth, Postgres, Storage, RLS, and optionally Edge Functions. Tables needed: profiles, competitions, competition_files, agents, agent_runs, agent_messages, output_versions, calendar_events, validity_checks, and optionally file_chunks for PDF retrieval.

Storage buckets: competition-files, agent-outputs, journal-pdfs, and profile-assets. RLS must be enabled on every exposed table. Users should only access rows scoped to their own user_id or later team membership.

6. AI Model Access

The app should support two execution paths: CLI-backed execution and API-key-backed BYOK execution. All model calls must go through server routes, never directly from browser components.

OPENCLAW_FORCE_CLI=1
OPENCLAW_PROMPT_TIMEOUT_MS=180000
OPENAI_API_KEY=
OPENROUTER_API_KEY=
ANTHROPIC_API_KEY=
GOOGLE_GENERATIVE_AI_API_KEY=

The model composer must expose model selection, reasoning effort selection, Tools, and web search toggle. Generation should be blocked until a model is selected.

7. Recommended Production Build Order

  1. Next.js App Router scaffold with Tailwind and shadcn/ui.
  2. Supabase auth, profiles, and app shell.
  3. Dashboard and competition CRUD.
  4. Storage uploads and file vault.
  5. Workbench pipeline and stage output documents.
  6. AI model router for CLI/API-key providers.
  7. Devs: Style Builder, custom agents, BYOK Models.
  8. Calendar event manager.
  9. Validity-Checker and PDF citation retrieval.
  10. Analytical Board/Dashboard.

8. Acceptance Criteria

  • User can create/select a competition and continue from the current stage.
  • Each agent has required input, produced output, and locked/ready/completed state.
  • User can override agent input with an uploaded .md file.
  • Stage output can be edited, saved, versioned, and approved.
  • Style Builder saves 00_style_profile.md to Vault.
  • Validity-Checker compares output and journal PDF side by side and supports AI citation review.
  • Supabase persists competitions, files, outputs, messages, calendar events, and validity checks.
  • AI model access works through server-side CLI or BYOK API keys.
